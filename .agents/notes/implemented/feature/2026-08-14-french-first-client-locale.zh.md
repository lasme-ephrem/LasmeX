# Agent Note: 法语优先的客户端 locale

Status: implemented

[English](2026-08-14-french-first-client-locale.md) | 中文

## 问题

LasmeX 定位为法语优先产品，但如果在每个浏览器 namespace 都有完整字典之前声明法语，就会暴露混合语言界面。无条件强制法语还会忽略浏览器明确请求的英语或中文，并破坏现有语言选择行为。

## 决定

客户端把 `fr`、`en` 和 `zh` 作为一个类型化 locale 集合提供。每个类型化 namespace 注册都提供三份字典，动态 namespace 也在英语和中文席位之外注册法语席位。注册表继续在编译期拒绝不完整的类型化注册。

全新浏览器按主子标签选择其请求的首个受支持语言。因此法语浏览器以法语打开，英语和中文浏览器保留所请求的语言；浏览器未请求任何已提供语言时，法语是产品回退。Host settings 文档载入后，显式 `locale.preference` 仍具有最高优先级。

法语也是活动语言缺少 key 时的查找回退。这样既让法语成为 LasmeX 产品基线，又保留有意的语言选择。Web 文档为静态外壳声明 `lang="fr"`；`LocaleRuntime` 会让该属性与每次浏览器或已存选择保持同步，使辅助技术能够识别当前字典。欢迎声明拥有完整法语文案，而不是拼接翻译片段。

## 影响

现在新增 locale 时，客户端只有在所有类型化 namespace 都具备完整字典后才能构建。法语文案覆盖主要对话、模型、设置、权限、工作区、工作流、子代理、Cordis、目录浏览、Session 导出，以及完整的 trajectory 时间线、账本、检查器、状态、错误、工具提示、JSON 复制操作和辅助技术界面。推理折叠区、skill 行、plan mode 失败、身份验证错误、内置权限名称与影响说明、脚注的辅助技术标题、Cordis 检查操作、工具行标题、输入／输出栏、检查按钮，以及结构化的 diff、read、search 和 web 卡片也通过各自所属字典解析，不再保留内联英语或中文标签。`grep`、`glob` 和 `pwsh` 等稳定 wire 名仍为技术标识符。英语和中文仍可选择，现有浏览器场景也继续有效。

locale 注册表之外仍可能存在内联字符串。对应界面本地化时必须把它们迁入所属 namespace；注册表无法发现从未声明为可翻译的文本。

## 考虑过的替代方案

| 替代方案 | 拒绝原因 |
|---|---|
| 无论浏览器语言如何都强制法语 | settings 载入前，浏览器明确请求英语或中文也不会生效。 |
| 只添加最显眼的法语字符串 | 缺失状态、错误和无障碍标签会造成混合语言产品。 |
| 用英语或中文作为缺 key 时的回退 | 一旦发生翻译缺陷，LasmeX 恰好会失去法语优先属性。 |
