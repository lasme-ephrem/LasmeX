# Agent Note: 任务活动派生自持久会话事实

Status: implemented

[English](2026-08-14-session-mission-activity-projection.md) | 中文

## 问题

任务仪表板需要在分页、重新加载和 Code Mode 中保持稳定的运行状态，但复制客户端窗口状态或添加面向展示的会话事件，会为持久日志已经记录的事实创建另一个权威来源。对外层 `run_code` 传输计数还会重复其实际子工具工作。

## 决策

`lasmex-session-mission` 在 `ctx.sessionProjections` 上注册仅宿主的 `missionActivity` 全日志投影。它折叠会话日志中已经存在的原生调用、Code Mode 子调度、待办事项快照、审批审计对和轮次结束。该投影不添加事件类型，也不修改 agent loop（智能体循环）或模型上下文。

该折叠排除外层 `run_code` 传输，并对其持久子调度事件计数。显式 Cordis 插件配置指定命令工具、用于分类验证且不区分大小写的 JavaScript 正则表达式源，以及保留的完整验证数组上限。无效或含糊的条目会使插件加载失败。在 `turn/end` 时仍处于打开状态的调用以中断失败结算，因此运行中状态不会跨越持久轮次边界。

该投影只公开消费方所需的运行事实：聚合的工具生命周期、有界验证命令和状态、不含原因的审批总数、最新完整待办事项快照，以及最新内置非成功轮次结果。其内部状态是纯 JSON，协议值由投影注册表进行 schema 验证。

## 考虑过的替代方案

**添加任务专用会话事件。** 源事件已经能够重建每个字段，因此新事件会复制持久权威并引入同步失败模式。

**折叠客户端会话窗口。** 分页和压缩会使窗口不完整；全日志宿主投影为实时、恢复和冷读取保留相同值。

**将 `run_code` 计为能力。** 它是围绕持久子调度的展示传输，因此对两层同时计数会夸大活动并隐藏实际执行工作的工具。

## 测试

包测试覆盖原生调用和 Code Mode 调用、shell 退出与策略标记、精确验证保留、格式错误和不匹配命令、轮次中断、审批和待办事项状态、延迟全日志回放、注册 dispose（资源释放），以及使用显式配置的真实 Loader 组合。

## 后果

消费方获得一个确定的运行投影，而无需重建跨事件关系或接收模型推理。验证分类有意保持部署特定，并且只识别使用 dsh shell 结果协议的已配置字符串命令工具；另一种命令协议需要显式适配器，而不是启发式推断。
