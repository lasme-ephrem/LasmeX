# Agent Note：客户端错误目录——每条线上错误都使用当前语言环境

Status: implemented

[English](2026-08-17-client-error-catalog.md) | 中文

## Problem

运行时失败以原始英文字符串到达界面：每个渲染器都手写了 `${error.message} (${error.code})`，导致 Toast、目标告警和命令失败界面把英文提供商消息混入本地化界面。新增一个 `RpcError` 代码时，没有任何一处地方指出「这个代码需要目录条目」。

## Decision

在 `lasmex-client-locale` 中自建客户端错误目录：

- `error-keys.ts` 把每个 `RpcError` 代码映射到 `error.*` 目录键，通过构造保证穷尽（`satisfies Record<RpcError['code'], string>`），因此新增主机代码会在客户端类型检查中失败，直到它获得键和字典条目。
- `describeError(error, t)` 是唯一展示器：目录查找，details 与主机消息作为插值参数，外加两个回退。未知线上代码，或类型联合早于某键的渲染命名空间，显示原始的 `${message} (${code})`——即旧格式——而不是回显目录键。
- 43 个代码位于共享 `common` 词汇表中（每部字典 44 个 `error.*` 键），每个渲染命名空间都可通过公共查找链访问。
- `LocaleRuntime` 服务在其 `common` 绑定之上暴露 `describeError(error)`；`InputBar` 与 `GoalBar` 通过各自的 slot 注入获得它（客户端 bundle 纯度门禁禁止跨插件值导入，因此目录以服务方法消费，绝不导入）。
- 工具调用界面保持 `name: code` 标识符的技术性——稳定标识符，不是散文。

## Alternatives considered

- **每个组件各自维护字典**——每个包携带自己的错误字符串，但 43 个共享代码会在每个包复制 44 个键，且彼此漂移。
- **逐字翻译提供商的 `message`**——提供商散文不够稳定，无法作为键，插值也会失效。
- **在主机侧本地化**——主机需要为每个连接携带语言环境上下文；错误只传输一次却在每个客户端呈现，因此客户端才是正确的一侧。
- **本地化工具调用的 `name: code` 标签**——它们是模型消费的标识符，翻译会破坏匹配；保持技术性。
- **在此变更中推翻 `ui-plan` 的英文错误界面策略**——超出范围；已记录的策略保持不变，可另行重新审视。

## Consequences

- 新增一个 `RpcError` 代码是两文件变更（主机错误映射加上 `error-keys.ts`）才能通过编译，随后每部字典一行——目录不可能悄悄落后。
- 未知线上代码退化为旧原始格式，而不是破坏渲染。
- 非技术性错误文案现在来自字典；语言环境套件对每个代码以法语字典覆盖验证，`input-bar` 与 `goalbar` 套件断言渲染后的文案。
- `ui-plan` 的失败字符串按现行错误界面策略保持英文。
